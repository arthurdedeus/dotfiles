# Getting-started pages

Use this pattern for a product setup flow with ordered required and optional steps.

## Structure

1. Current frontmatter copied from a recent getting-started page.
2. Beta warning when the product is in beta.
3. One or two sentences stating the outcome.
4. Ordered setup steps.
5. A visible verification step.
6. Links to deeper configuration and troubleshooting.

Use `QuestLog` only when current pages for that product family use it.

## Step rules

- Start each title with an action.
- Mark the step required, recommended, or optional when useful.
- Explain one concept per step.
- Put the action before background.
- Show the relevant UI only when it reduces ambiguity.
- End with a clear next action or verification.

Keep advanced detail on dedicated pages. A getting-started page should get a new user to a working result.
