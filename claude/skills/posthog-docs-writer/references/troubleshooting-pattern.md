# Troubleshooting and FAQ pages

Use question headings that match what a reader would search for.

## Answer pattern

1. Give the direct answer first.
2. State the likely checks in diagnostic order.
3. Show the expected result for each check.
4. Explain relevant limits or edge cases.
5. Link to deeper setup or reference material.

For a failure question, use a numbered checklist. Start with the fastest, safest check.

For a support question, state unsupported behavior plainly. Do not hide a limitation behind background text.

Use the current AI-help or support component only when nearby pages use it. Verify its current API before adding it.

If an answer grows beyond a few short sections, create or link a dedicated page and keep the FAQ answer brief.
