# Product docs pages

Use this pattern for a feature, dashboard, setting, or integration.

## Structure

1. Current frontmatter from a nearby page.
2. A direct opening that states what the feature does.
3. Task or concept sections in the order readers need them.
4. Screenshots for UI states that text cannot show clearly.
5. Limits, permissions, and failure behavior.
6. Links to related setup or reference pages.

## Section rules

- State the result first.
- Explain calculations or data sources when they are not obvious.
- Use tables for comparable fields, not ordinary prose.
- Link to the exact app surface when the current docs do so.
- Avoid repeating content maintained elsewhere.

For integrations, cover data flow, setup, authentication, stored data, sync behavior, errors, and removal.

For dashboards, explain each metric's meaning, calculation, filters, and known limits.
